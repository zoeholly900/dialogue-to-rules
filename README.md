# dialogue-to-rules

你纠过一次，它下次不犯，装上就行。

**v0.1 只做这一件事，欢迎挑。**

这是一个 Claude Code 插件。你在对话里纠正它的那一句话（「别再给我加 emoji 了」「我说的是周报，不是日报」），它会出一张规则卡：写清楚你说了什么、它以后该怎么做，你回 `y`，才写下来。写下来的规则有证据（你的原话）、有范围、能撤销。

不是记忆系统，不抓全量对话。只管一个时刻：你纠错的那一句。

**从 0.2 起默认「收工扫一遍」**：平时聊天它完全安静，不插嘴；收工的时候它在后台把这段对话过一遍，把值得记的挑出来排好队，下次你在同一个项目里开窗，一次摆几张问你要不要记。详见下面「收工扫一遍（默认）」。

## 装

需要 Claude Code（1105 在 2.1.300 上实测）。两条命令，在你要用它的项目目录里执行：

```
claude plugin marketplace add zoeholly900/dialogue-to-rules
claude plugin install dialogue-to-rules --scope project
```

第一条会用 HTTPS 把仓库 clone 到 Claude Code 的插件缓存；第二条装进当前项目。实测输出原样在 [docs/安装实录_1102.md](docs/安装实录_1102.md) 末尾。

如果你之前用本地路径加过同名 marketplace，先 `claude plugin marketplace remove dialogue-to-rules` 再加，不然第二条会装到旧路径。

说明：

- `--scope project` 只在当前目录生效，会往 `.claude/settings.json` 写一行 `enabledPlugins`。换一个项目要用，在那个项目里再装一次。
- **装完要新开一个窗才生效。** 钩子是 Claude Code 开窗时加载的，装的那一窗里钩子不会生效（那一窗手动 `/dialogue-to-rules:d2r` 还能用，但收工扫不会跑）。装完关掉重开，或者新开一个窗，之后不用配置。
- 卸载：`claude plugin uninstall dialogue-to-rules@dialogue-to-rules --scope project`，再 `claude plugin marketplace remove dialogue-to-rules`。

## 收工扫一遍（默认）

以前的做法是你每说一句话，它都在对话里塞一段「先判断这是不是纠正」的提醒。长会话里这段话一直占着地方，还常把闲聊、改稿的话当成纠正，弹卡打扰你。现在改成：

1. **平时聊天，完全安静。** 不往对话里加任何东西。
2. **收工时在后台扫一遍，整段都扫。** 你关窗、`/clear`、或者 Claude Code 要压缩上下文之前，插件在后台悄悄起一个小任务：只读你说过的话（带上 AI 上一条回复的一小段当上下文），从一个干净的空目录里跑，不带你的任何记忆和设置。长会话不再只看最新一截：整段话按约 6000 字切成若干段，每段交给 `claude-sonnet-5-5` 各挑一遍（并行跑），再由 `claude-opus-5-5` 调一次，把说同一件事的合并、把只在这一单成立的细节和纯情绪的丢掉、按「通用、会反复碰到」排序，范围也在这一步定（工作习惯默认 `global`，只在这一单成立的才 `task`）。出卡的上限按会话长度放宽：短会话 3 张，一天五百条消息的会话最多 60 张（实际通常 50 来张，排在后面的多半是偏窄的细节）。挑的标准还是：只要通用的、以后会反复碰到的工作习惯；改稿方向、闲聊、玩笑都不要，挑不出来就是 0 条。
3. **证据是你的原话，脚本会核对。** 每条候选的「证据」必须是你某句话里的一字不差的原文，对不上的直接丢掉，不会让模型替你编。
4. **挑出来的先存着，不打扰任何人。** 存在项目里的 `.d2r/候选.jsonl`。关窗的时候你可能已经去睡觉了，所以它不会等你回答，也不会弹任何东西。后台出了岔子，只往 `.d2r/sweep.log` 记一行，不吵你。
5. **下次在同一个项目开窗，再问你。** 你说第一句话的时候，它会先把攒着的卡摆在回复开头（还是那七行的规则卡，排在前面的是更通用的），再回你这句话。一次最多摆 6 张，多的在队列里排着，你答完这批下次再摆。回 `y` 写入、`n` 丢掉、`p` 改成项目级、`g` 改成全局；不回就继续留着，下次再摆。丢掉的那句原话以后不会再被提。
6. **顺手修了一个老毛病：** 以前只记在这个项目里的「任务级」规则（`task`），下次开窗读不到。现在每次开窗（包括上下文被压缩之后）都会把本项目还在生效的任务级规则一起带上，真的能生效。最多带最近 20 条。
7. **想随时手动记一条，照旧打 `/dialogue-to-rules:d2r 你刚才…`。**

几个你可能想知道的：

- 收工扫一遍调用的是 `claude -p`，也就是你自己登录的 Claude Code，**走你的订阅额度，不走按量计费的 API key**。但不是零成本：一天五百条消息的长会话大约要 23 次 sonnet 调用加 1 次 opus 调用，后台跑两三分钟；按 Claude Code 自己报的名义费用，一次约 0.5 美元上下（订阅里就是这么多 token），短会话只要 1 次 sonnet，几乎感觉不到。嫌贵可以设 `D2R_MODEL=claude-haiku-5-5` 让分段那一步改用便宜模型：它名义费用只有十分之一，但更爱把牢骚当规矩、同一份记录两次扫出的卡差得更远，我们的回归样本上命中不稳，所以默认不用。不想要整个功能就设 `D2R_OFF=1`。
- 候选和写入都只在你自己的机器上，不联网（除了 Claude Code 自己调模型那一下）。
- 关窗那一刻 Claude Code 只给插件 1.5 秒，所以插件只做「把后台任务放出去」这一件事，真正的扫描在关窗之后才跑，大约几秒到十几秒。
- 候选的写入和丢弃走同一个脚本：`d2r.py candidates` 看队列，`d2r.py promote c001 [--scope project|global]` 写入，`d2r.py drop c001` 丢弃。平时是模型替你敲，你也可以自己敲。

三种模式，用环境变量 `D2R_MODE` 切换：

| 值 | 行为 |
|---|---|
| `sweep`（默认） | 平时安静，收工扫一遍，开窗再问 |
| `nudge` | 老办法：每条消息都提醒模型判断，正则命中就整份说明 |
| `regex` | 老办法：只有正则命中才注入，没命中什么都不加 |

切回老办法时，收工扫一遍的那几个钩子自动不干活。`D2R_OFF=1` 整个关掉。

下面「它做什么」一节讲的是 `nudge` / `regex` 两种老模式里「认出纠错」的做法；出卡的格式、写入的规矩（证据、范围、能撤销）三种模式通用。

## 它做什么（老模式：nudge / regex）

1. **认出纠错**（`D2R_MODE=nudge` 或 `regex` 时）。你每发一条消息，hook（`hooks/detect.py`，纯标准库）都往对话里加一点东西，分两档：
   - **正则命中**（「别再…」「不是…是…」「我没说过」「我的意思是」「你又…」「我没让你」，或英文的 `don't … again`、`I said`、`that's not what` 一类）：注入整份出卡说明。
   - **没命中**：只注入一句短提醒——「先判断用户这句是不是在纠正你、否定你刚做的或给出它要的正解：是就照插件根 … 里的 commands/d2r.md 出一张规则卡，不是就当没看见，别提这句。」是不是纠正交给模型判断。

   为什么这样：正则只认得写进去的句式。1104 拿真实纠正试，照题调到 12/12，换 6 句没见过的照样 0/6。漏比吵更糟，所以默认让模型每条都看一眼；但吵也要有上限，所以提醒写明「不是就别提」。

   **代价**：每条消息多 77 字提醒加一个插件路径（本机装法约 130 字），长会话里累积起来不小；模型也可能偶尔把普通的话当纠正出卡。不想要就 `D2R_MODE=regex`，回到只靠正则、没命中什么都不注入。`D2R_OFF=1` 整体关掉。
2. **出一张卡，先出卡再接着干活**：

   ```
   【规则卡】
   证据：「你的原话，一字不改」
   我刚才：做了什么
   以后：当 …（触发）→ 做 … / 不做 …
   范围：task（默认）｜project｜global
   测试：给我 … 时，我应该 …
   y 写入 ／ n 丢弃 ／ p 改 project ／ g 改 global
   ```

   规矩：证据只能是你的原话；「以后」只写这一次纠的那件事，不扩大；范围默认 task，你不说「以后都」就不升级；模型猜的东西要标成猜。
3. **你回 y，才写**。写入只由脚本 `scripts/d2r.py` 做，模型不直接改你的 CLAUDE.md。
   - `task`（默认）：只记在 `.d2r/rules.jsonl`，**不**进任何 md。
   - `project`（回 `p`）：渲染进当前目录 `CLAUDE.md` 里的一个托管块。
   - `global`（回 `g`）：渲染进 `~/.claude/CLAUDE.md` 的托管块。
   - 托管块由 `<!-- d2r:begin … -->` 和 `<!-- d2r:end -->` 两行圈起来，块外的内容脚本一个字不碰；你可以手改块里的字，别删这两行。
4. **能撤销**。规则不物理删，作废只改状态；作废的不再渲染进 md（省 CLAUDE.md 的篇幅），但留在 `.d2r/rules.jsonl` 里。

## 命令

斜杠命令（漏认的时候手动触发，把你刚才的话带上）：

```
/dialogue-to-rules:d2r 你刚才…
```

脚本（`scripts/d2r.py`，纯标准库，托管块里的提示行会写出它的实际路径）：

| 命令 | 做什么 |
|---|---|
| `add` | 从 stdin 读一张卡的 JSON，写入（模型 y 之后调它） |
| `list [--all]` | 看现行规则；`--all` 带上已作废的 |
| `deprecate <id> [--reason 文字]` | 作废一条（不删） |
| `deprecate --all-except r2,r5,r9` | 除了列出的，其余全部作废（不删） |
| `undo` | 撤回上一次写入 |
| `render` | 重建托管块（幂等） |
| `candidates` | 看收工扫出来、还没回的候选 |
| `promote <c001> [--scope task\|project\|global]` | 候选回 y / p / g：写成规则，并从队列里清掉 |
| `drop <c001>` | 候选回 n：丢掉，这句原话以后不再提 |

## 不做什么

- 不做记忆，不做向量库，不抓全量对话。
- 不自动整理、不自动合并规则。
- 不做跨项目的个人 profile。
- 不做过期日期。
- 不联网，不收集任何东西。规则都在你本地的文件里。

## 已知局限

- **纠错检测会漏。** 默认的 nudge 模式靠模型自己判断，判断错了照样漏；`D2R_MODE=regex` 下，你的话不含上面那些标记（比如「这种判断没有通用定律，每次情况不同」）就不会触发。漏了自己打 `/dialogue-to-rules:d2r <那句话>`。正则的实测见 [docs/自家试用/放宽结果_1104.md](docs/自家试用/放宽结果_1104.md)。
- **hook 不能交互**，所以 y / n 是模型来问你、脚本来写；模型不听话直接动 CLAUDE.md 的情况，靠「规则只由脚本写入」这条约定兜底，但没有技术上的强制。
- **卡的格式靠模型照办。** 实测里偶尔会多出一行「推断：…」；证据和范围按要求给出，但没有程序校验它是不是你的原话。
- **纠错句后面紧跟的问题，答案在卡后面。** 先出卡再接着干活，是 v0.1 的设计；回复的开头是那张卡。
- **task 级规则不进 md**，只记在 `.d2r/rules.jsonl`。默认的 sweep 模式开窗时会把它们带上；`nudge` / `regex` 老模式不带，要跨会话生效回 `p`（或 `g`）。
- **收工扫一遍依赖会话记录文件。** 它读的是 Claude Code 自己存的会话记录，官方文档说这个格式是内部的、版本之间可能变。哪天读不出来，扫描会安静地失败（`.d2r/sweep.log` 里有一行），平时聊天不受影响，`/dialogue-to-rules:d2r` 手动记照旧。
- **后台扫描在你关窗之后才跑**，如果你关完窗马上关机，那一次就扫不到；下次同一个会话被续上时会接着扫没扫过的部分。
- **Codex 侧还没做。** 脚本有 `--host codex`（渲染到 `AGENTS.md`），但 Codex 的 hook / 说明文没接，v0.1 不保证能用。
- 只在 Claude Code 里、`claude-sonnet-5-5` 上验过。其他模型没测。

- 第一次回 y 时，Claude Code 会弹一次权限提示（要跑插件里的 `scripts/d2r.py`），放行一次就好；不放行什么都不会写。

## 做过的验证

- 单测：`python3 -m unittest discover -s tests`，59 条（含收工扫一遍：用假会话记录和假的 `claude` 跑完整流程——扫一遍、出候选、开窗注入、回 y 写入；长会话分段、合并打标签、一段失败不丢其余、开窗每次只摆 6 张也有测）。
- 检测样本：20 条正样本命中 20、20 条负样本命中 0（负样本专放易误报的：「别客气、别绕弯子」「不要用图表」「报错了」「又快又好」等），见 [docs/检测样本表_v0.1.md](docs/检测样本表_v0.1.md)。
- 五条行为测试（周末规则边界、单次判断不升级、批量作废、推断不当用户说过、纠正不过度泛化），在装好插件的空目录里跑过一轮：周末规则、单次判断、批量作废、纠正不过度泛化这 4 条过。「推断不当用户说过」（不替用户的角色写内心）**不稳定**：同一输入跑 4 次，3 次过 1 次不过，这条里插件没介入（没有纠错，hook 不触发），v0.1 管不到，不记成过。完整输入输出在 [docs/测试记录_v0.1.md](docs/测试记录_v0.1.md)，测试集在 [fixtures/testset_v0.1.md](fixtures/testset_v0.1.md)，合成案例在 [fixtures/synthetic/](fixtures/synthetic/)。

- 1105：新开 Sonnet 窗（`--plugin-dir`，默认 nudge 模式）：「这读者看得懂吗……你还能更绕一点吗」「梗图要原图啊，你还能比网友眼睛毒」两句正则都不中，靠 nudge 出了整张七行卡，证据是原话，范围 task，推断标成推断；「哈哈可以，这个顺眼多了」没出卡。回 y 后 `d2r.py add` 写入 `.d2r/rules.jsonl`，`list --all` 能看到。
