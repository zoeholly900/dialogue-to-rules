# dialogue-to-rules

**它会自己记，不要就说「撤」。**

你在对话里纠正 Claude 一句（「以后给我路径都单独一行，别再带句号了」），它在同一条回复的最后跟一行：

```
📌 记下了：给路径单独一行不跟标点｜适用：给用户任何文件或文件夹路径时。不要就说「撤」
```

你什么都不用回，这条就生效了：写进这个项目的 `CLAUDE.md`，下次开窗照样遵守。不想要，回一个字：**撤**。

那一行容易被滚过去，所以同时弹一条系统通知，第一排就是那句规矩：

```
规矩+1：给路径单独一行不跟标点
适用：给用户任何文件或文件夹路径时
                                  [撤]  [看看]
```

点「撤」就作废这条（再弹一条「规矩-1：…」），点「看看」或点通知本身，打开「规矩本」并跳到这条；不点，过一会儿自己消失，照常生效。规矩本是一个网页，所有记下的规矩都在上面，最新的在最上，每条写着规矩、适用、证据原话、什么时候记的、管哪个项目、生效还是已撤。随时说一句「规矩本」，它就把页面路径给你。

只有你自己说明是规矩（「以后」「每次」「别再」「又」「说过」……）、换个任务还会碰到的才记；改这一次的稿、闲聊、玩笑不记。宁可少记。

## 装

需要 Claude Code（在 2.1.300 上实测）。在你要用它的项目目录里：

```
claude plugin marketplace add zoeholly900/dialogue-to-rules
claude plugin install dialogue-to-rules --scope project
```

**装完新开一个窗才生效。** 卸载：`claude plugin uninstall dialogue-to-rules@dialogue-to-rules --scope project`。

## 你只需要知道这些

- **撤**：刚记的那条作废（不删，能恢复）。也可以说「不要这条」「别记」。
- **漏了**：打 `/dialogue-to-rules:d2r 你刚才…`，它就记。
- **规矩本**：说「规矩本」拿到路径，或者直接打开 `~/.d2r/规矩本.html`。
- **不想用了**：设环境变量 `D2R_OFF=1`。只关通知：`D2R_NOTIFY=0`。
- 规则写在哪：本项目的进 `./CLAUDE.md`，它判断「所有项目都成立」的（那一行会写「记下了（所有项目）」）进 `~/.claude/CLAUDE.md`。都在 `<!-- d2r:begin -->` 到 `<!-- d2r:end -->` 之间，块外一个字不碰。

## 进阶（用不着可以不看）

### 怎么做到的

- **开窗时说一次规矩**（`hooks/live.py`，SessionStart）：告诉模型什么时候该记、那一行怎么写。只在开窗和压缩上下文之后各说一次，平时每条消息不加任何东西。
- **那一行由插件写，不由模型写**（Stop 钩子）：回复结束时，插件读这条回复里的「📌 记下了：<规矩>｜适用：<…>」，交给 `scripts/d2r.py` 写成规则。模型不用跑命令，所以不会弹权限框，也不用你回 y。证据是你那一轮说的原话（话太长就取跟规则最贴的那一句，一字不改）。代码块里的、没填的模板不算。
- **格式是闸，不靠模型自觉**：只认「规矩｜适用：…」两段，规矩最多 16 字、适用最多 20 字。不合格的那一行不记，插件当轮让模型补一行合格的（只让补一次）；还是不合格，就把规矩截短写进去，规矩本里标「格式不全」，原句整句留在 `CLAUDE.md` 给模型看。0.3.1 及以前记的老规则不改格式，规矩本里原样显示。
- **撤也由插件做**（UserPromptSubmit 钩子）：只有当你这句话就是「撤」「不要这条」这类短话、而且上一条回复刚记过一条时，插件才把那条作废，再让模型回一句撤了哪条。上一条回复没记东西，你说「撤」它不动（你可能在说撤稿）。
- 写进去万一失败，你会看到一行「dialogue-to-rules：这条没记上」，不会让「记下了」成为假话。日志在 `.d2r/live.log`。
- **通知**（`hooks/banner.py`）：插件写入或撤掉一条时发一条系统通知。标题「规矩+1：<规矩>」/「规矩-1：<规矩>」，副标题「适用：…」。钩子从不等它，也从不弹必须回答的对话框。`D2R_NOTIFY=0` 关掉。
  - macOS 优先用 [alerter](https://github.com/vjeantet/alerter)：带「撤」「看看」两个按钮，30 秒没点就消失。等你点的是一个后台小进程，不是钩子。要让按钮一直露在外面，得在 系统设置 › 通知 › alerter 里把样式设成「提醒」；设成「横幅」时按钮藏在鼠标移上去才出现的「选项」里。
  - 没有 alerter 就用 [terminal-notifier](https://github.com/julienXX/terminal-notifier)：没按钮，点通知打开规矩本那一条（`-group d2r`，通知中心里只留最新一条）。
  - 这两个本机都没有的话，插件第一次发通知时在后台从它们的 GitHub 官方 release 下到插件自己的 `vendor/`（不用 brew、不碰系统目录），按 GitHub 给这个文件登记的 sha256 核对，对不上就不装；下载失败一天后再试。
  - 还没装上时退回 `osascript` 的 `display notification`：能看不能点（点了只会打开「脚本编辑器」），正文末尾写「看全部：说「规矩本」」。看不到通知就去 系统设置 › 通知 › 脚本编辑器 打开允许通知。
  - Linux 有 `notify-send` 就用（同样不能点，末尾带「看全部」），都没有就不发。
- **规矩本**：`~/.d2r/规矩本.html`，单个网页，本机所有记过规矩的项目（登记在 `~/.d2r/projects.json`）加全局规则都在上面，最新的在最上，含已撤的。每次写入、作废、撤回都自动重建；`d2r.py book` 手动重建并打印路径。通知点开的是 `~/.d2r/规矩本_跳转/<那条>.html`，它把你带到规矩本里那一条（文件地址带 `#` 锚点，交给系统打开时会被丢掉，所以多这一跳）。
- 写入、作废、撤回都只由 `scripts/d2r.py` 做，作废不删，只改状态；作废的不再进 `CLAUDE.md`，留在 `.d2r/rules.jsonl` 里。

### 模式（环境变量 `D2R_MODE`）

| 值 | 行为 |
|---|---|
| `live`（默认） | 开窗说一次规矩，纠正那一轮当场记，撤就作废 |
| `sweep` | `live` 再加收工补扫：关窗、`/clear`、压缩前在后台把整段对话过一遍，捡 `live` 漏掉的，同样直接生效，下次开窗一行告诉你 |
| `nudge` | 每条消息都提醒模型判断一次（占上下文，老办法） |
| `regex` | 只在正则认出纠错句式时提醒（老办法） |

四种模式记下来的都是同一行「📌 记下了」，都只要你知道「撤」。`D2R_OFF=1` 全关。

### 收工补扫（`D2R_MODE=sweep`）

默认关着：当场记已经接住了大部分；补扫要花额度（下面有账），而 1114 在自家一天 503 条消息上扫出 0 条。打开后：只读你说过的话，从一个干净的空目录里调 `claude -p`（分段用 `claude-sonnet-5-5`，合并去重用 `claude-opus-5-5`），证据必须是你的原话、脚本逐字核对；出不出、出几条按你自己的信号定（同一件事说了几遍、强调词、火气），不是模型打分。挑出来的直接写成规则，记进 `.d2r/待告知.jsonl`，下次开窗在第一条回复末尾一行告诉你：「📌 之前还记下了：…。不要就说「撤」」。

补扫调用的是 `claude -p`，也就是你自己登录的 Claude Code，**走你的订阅额度，不走按量计费的 API key**。但不是零成本：一天五百条消息的长会话大约要 24 次 sonnet 调用加 1 次 opus 调用（带上 `known_files` 时那 1 次 opus 的输入会大不少），后台跑三分钟上下；按 Claude Code 自己报的名义费用，一次约 0.8 美元上下（订阅里就是这么多 token），短会话只要 1 次 sonnet，几乎感觉不到。嫌贵可以在配置里把 `chunk_model` 改成 `claude-haiku-5-5`（见下面「补扫按自己的说话习惯调」）让分段那一步改用便宜模型：它名义费用只有十分之一，但更爱把牢骚当规矩、同一份记录两次扫出的卡差得更远，我们的回归样本上命中不稳，所以默认不用。

### 补扫按自己的说话习惯调

不同人说话习惯不一样，不同模型脾气也不一样：有人急了才说「求求了」，有人从来不说；有人一个月只纠正三次，有人一天三十次。所以收工补扫「记不记、记几条、先记哪条」都做成了你能改的配置（只对 `D2R_MODE=sweep` 有用）。**不配也能跑**，下面全是可选的。

放哪里：`~/.d2r/config.json` 是全局一份，`<项目>/.d2r/config.json` 可以按项目覆盖（逐项覆盖，没写的项沿用全局，再没写就用默认）。完整示例在 [docs/config.example.json](docs/config.example.json)。写错了（不是合法 JSON、值的类型不对）不会出事，那一项用默认，一行记进 `.d2r/sweep.log`。想看现在到底生效了什么：`python3 hooks/sweep.py config`（在插件目录里跑）。

它怎么给一张卡打分：先看你**自己**的信号，不看模型的主观打分。同一件事你说了几遍（说了几遍加几分，最多算 3 遍）、你的话里有没有强调词（命中一个词加 `keyword_points` 分，最多算两个词）、带不带火气（加 1 分）。分数高的先记。

| 配置项 | 干什么用 | 默认 | 例子 |
|---|---|---|---|
| `keywords` | 你自己的口头禅、强调词，命中就加分。**加在内置词表后面**，不是替换。内置词表里有「求求、说一百遍、下次又、别再、以后、所有窗、通用、难道、凭什么」这一类 | `[]` | `["说烂了", "跟你说过"]` |
| `use_default_keywords` | 设成 `false` 就只认你自己写的词，内置词表不用 | `true` | `false` |
| `keyword_points` | 命中一个词加几分 | `3` | `5`（你的口头禅很少，一说就是真急了，就调高） |
| `max_per_day` | 严厉度之一：一天（五百条消息上下的会话）最多出几张卡，短会话按比例少出，最少 3 张 | `10` | `5`（只想要最要紧的几条） |
| `min_score` | 严厉度之二：低于这个分数的不出卡 | `3` | `6`（要重复好几遍、还带强调词才出） |
| `repeat_times` | 同一件事你说到第几次才出卡；**只说一次但带强调词的照出** | `2` | `1`（说一次就出，适合话少的人）；`3`（只记反复说的） |
| `known_files` | 严厉度之外的去重：额外读哪些文件当「已经记过」，说的是同一件事就不再出。默认空，这个插件默认只读自己的规则文件，不碰你别的文件。相对路径从项目目录算 | `[]` | `["~/.claude/projects/-Users-me-work/memory/MEMORY.md"]` |
| `chunk_model` | 按段读对话用哪个模型。每个人的订阅不一样，Max 用户可以换更强的，额度紧可以换便宜的 | `claude-sonnet-5-5` | `claude-haiku-5-5` |
| `merge_model` | 最后合并、判断、去重那一次调用用哪个模型（只调一次，所以可以用强的） | `claude-opus-5-5` | `claude-sonnet-5-5` |

**`known_files` 的判断是留了凭据的**：合并那一步判断一张卡「已经记过」时，必须把你文件里那一条的原文抄出来，脚本核对这段原文真的在文件里才算数；模型凭印象说「好像记过」不算，卡照出。这样不会因为模型「觉得像」就把你真正想要的卡吞掉。

几个调法：

- **嫌卡太多**：`max_per_day` 降到 5，或者 `min_score` 提到 6。
- **嫌漏了**：`repeat_times` 设成 1，或者把你的口头禅加进 `keywords`。
- **你从不说强调词**：`use_default_keywords` 设成 `false`、`keywords` 留空，那就纯靠「同一件事说了几遍」；这时 `repeat_times` 要 ≥ 2，否则出不来卡（说一次又没强调词，分数是 0）。
- **别的工具已经替你记了一份**：把那份记忆索引的路径写进 `known_files`，这里就不重复出。

### 命令（`scripts/d2r.py`，纯标准库；托管块里的提示行写着它的实际路径）

| 命令 | 做什么 |
|---|---|
| `list [--all]` | 看现行规则；`--all` 带上已作废的 |
| `retract` | 撤掉这个项目里最近记的一条（说「撤」时插件做的就是这个） |
| `book` | 重建规矩本，打印路径 |
| `deprecate <id> [--reason 文字]` | 作废一条（不删） |
| `deprecate --all-except r2,r5,r9` | 除了列出的，其余全部作废（不删） |
| `undo` | 撤回上一次写入或作废 |
| `add` | 从 stdin 读一张卡的 JSON 写入（`{"trigger","action","prohibit","scope","evidence":{"quote"}}`） |
| `render` | 重建托管块（幂等） |
| `migrate` | 把 0.2 留下的候选池（`.d2r/候选.jsonl`）全部转成规则；开窗时插件会自动做 |
| `candidates` / `promote <c001>` / `drop <c001>` | 0.2 的候选池命令，留给想手动处理的人 |

### 从 0.2 升上来

0.2 是「收工扫一遍、下次开窗摆卡问 y/n」。实际用下来：卡隔一两天才弹，那时已经忘了来龙去脉，一张都没人回。0.3 改成当场记、默认生效。升级后第一次开窗，候选池里还挂着的卡会自动转成规则，并在你第一句话的回复末尾一行告诉你；不要就说「撤」。0.2 的 `task` 范围不再默认出，还在生效的 `task` 规则照旧每次开窗带上。

### 已知局限

- **记不记靠模型判断。** 会漏（漏了打 `/dialogue-to-rules:d2r`），也可能把不该记的记了（说「撤」）。1116 实测里一次性改稿意见被记过一次，收紧说明后同样的话不再记，但不保证不再发生。
- **「撤」只管上一条回复刚记的那条。** 隔了几轮再想撤，说「撤掉那条路径的规则」之类，模型会用 `list` / `deprecate` 去做（第一次会弹一次权限框）。
- **只读回复里的最后一条消息。** 那一行要写在回复最末尾；写在中间某段、后面又调了工具的，可能读不到。
- **证据是你那一轮的话。** 纠正发生在好几轮之前、那一轮只说了「对，记一下」的，证据就是「对，记一下」。
- 依赖 Claude Code 的 Stop 钩子带 `last_assistant_message`（2.1.300 有）；没有时退回读会话记录文件，那个格式官方说是内部的、可能变。
- **Codex 侧还没做。** 脚本有 `--host codex`（渲染到 `AGENTS.md`），钩子没接。
- 只在 Claude Code、`claude-sonnet-5-5` 上实测过。

### 不做什么

不做记忆、不做向量库、不抓全量对话；不自动整理合并规则；不做跨项目的个人 profile；不联网，规则都在你本地的文件里（补扫打开时除了 Claude Code 自己调模型那一下）。

### 做过的验证

- 单测：`python3 -m unittest discover -s tests`，109 条。当场记那部分在 `tests/test_live.py`：纠正那一轮出的那行被写成规则、证据是原话、「所有项目」进全局、默认生效进 `CLAUDE.md`；说「撤」作废、只认上一条回复刚记的、别的窗和别的话不误撤、`undo` 能恢复；开窗只说一次规矩且里面没有 y/p/g；0.2 候选池自动转规则并只告知一次；写失败会提示。
- 1116 本机实测（干净的 `claude -p --plugin-dir`，`claude-sonnet-5-5`）：纠正「以后我要路径，就只给路径那一行」→ 回复末尾出了「📌 记下了（所有项目）：…」，规则写进全局托管块；下一轮说「撤」→ 作废、托管块里消失、模型回「撤掉了这条」。项目级纠正（「这个仓库测试一律 unittest，别再提 pytest」）落在项目 `CLAUDE.md`。
