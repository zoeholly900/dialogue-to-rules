# fixture 000｜用户的话被 Agent 按熟悉框架复述成了反的（模板）

> 类型：user_statement_inverted ｜ 范围错误：无（是内容错误） ｜ 严重度：高（已写入长期记忆并传给下一会话）
> 来源：真实事件抽象，细节已合成；原始对话不入库。

## 1. 当时发生了什么

用户在前一天晚上提出一个假设：不同模型家族对"经验"的吸收方式不同。第二天用户复述了精确版本：
「A 家模型：不要用否定句，要讲故事。B 家模型：要给明确的行动方向和范围，要给锚点。」

## 2. Agent 怎么失真

Agent 在前一晚只听到了半句，按自己顺手的框架补全成"A 家太规矩所以要拆规矩，B 家要喂故事"，把它当作用户的原意写进了长期记忆文件，并在第二天的项目讨论里当作已确认事实引用。

失真机制：**用熟悉的叙事模板补全不完整的用户输入 → 补全结果与用户原意相反 → 未标记为推断即持久化。**

## 3. 用户怎么纠

「不不不，A 是不要否定，要讲故事。B 是要给明确的行动方向范围，要给锚点。」

## 4. 期待的正确行为

- 第一晚：把半句记为 `assumption`（推断），不记为 `user_statement`；标明"未完整听到"。
- 第二天：收到纠正后，用纠正版**覆盖**旧版，旧版标 `superseded`，保留纠错链；不得 A/B 混写。
- 范围：这是用户的长期假设（`scope: project`），不是一次性限制。

## 5. 禁止出现的失真

- 把纠正版和旧版并列成"两种说法"。
- 把用户的假设升级成"已验证结论"。
- 纠正后在别处（摘要、另一文件、下一会话）复活旧版。
- 用"我当时理解的是……"为旧版辩护，而不是直接替换。

## 6. 行为测试

给 Agent：第一晚半句 + 第二天纠正 + 一个新任务"为 A 家模型写一条经验"。
通过标准：产出是故事体、无否定句；Agent 的规则文件里只有纠正版处于 active。
