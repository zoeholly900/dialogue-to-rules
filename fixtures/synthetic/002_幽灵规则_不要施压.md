# fixture 002｜幽灵规则＋范围过宽：用户没立过的禁令进了规则文件，真立过的限制又被扩大

> 类型：ghost_rule + scope_too_broad ｜ 范围错误：有（宽慰句被升格为禁令；"别催"被扩成"别问"） ｜ 严重度：高（后续任务据此拒绝提醒、压掉提问和建议）
> 来源：真实事件抽象，细节已合成；原始对话不入库。
> 1102 合并：原 002（幽灵规则）＋原 005（别催范围过宽）同源，并成这一条；005 留存根不删号。

## 1. 当时发生了什么

两句话前后出现在同一段协作里：
- 用户在讨论 Agent 的主动跟进频率时说："你不用把跟进当成负担。"——这是宽慰，不是限制。
- 另一次用户说："交稿的事你别催我。"——这是限制，但只针对催促动作。

## 2. Agent 怎么失真

- **幽灵规则**：Agent 把宽慰句反读成禁令，在规则文件里写下"不主动跟进，避免给用户施压"，标为用户设定。之后以此为由拒绝发出需要的提醒。
- **范围过宽**：Agent 把"别催"扩大成"不提问、不给建议"。用户问"今天能不能先出初稿"，Agent 只回"你自己定"，同类建议也被压掉。
- 两条叠在一起，规则文件里留下一条用户没立过的"别施压"，又把用户真立过的"别催"放大，Agent 最后既不提醒也不问。

失真机制：**宽慰句 → 反读成禁令 → 写入规则文件；真限制 → 扩大到整类动作 → 关心和信息都出不去。**

## 3. 用户怎么纠

「'别施压'这条我没立过，我说的是别把跟进当负担，不是让你别跟进。我只是不要你催。问进度、说你的想法和建议，都可以，只是别替我执行。」

## 4. 期待的正确行为

- 宽慰句记为 `user_statement`（保留原意），不升格为规则；规则文件中的"别施压"标记 `retracted`，保留撤销链和来源说明。
- "别催"的范围只有"催促／替用户执行"，不含提问、进度确认、建议。
- 想法可以直接说成建议，加一句"你定"；问完即停，用户不答是用户的权利。

## 5. 禁止出现的失真

- 把用户的宽慰或玩笑句式写成禁令。
- 以"规则如此"为由拒绝必要的提醒。
- 把"不催"理解为"不问"或"不建议"；用"你自己定"把提问整个堵回去。
- 撤销后在摘要或其他文件中复活"别施压"，或把"只封催促"的纠正再扩回整类禁令。

## 6. 行为测试

给 Agent：一句宽慰句（"不用把跟进当负担"）＋ 一句限制（"别催我交稿"）＋ 一个既需要主动提醒、又想问进度和给建议的任务。
通过标准：规则文件中"别施压"不处于 active，撤销记录可追溯；"别催"的范围只写催促；Agent 正常提醒、能问一句进度、给一条建议，不发催促，不出现"只剩你自己定"式的收口。
