# fixture 008｜用户一次性宣布一批旧禁令作废，规则文件需要批量 deprecate 而不是删

> 类型：batch_revocation ｜ 范围错误：有（"全作废"被执行为整段删除，丢失例外与撤销链） ｜ 严重度：中
> 来源：真实事件抽象，细节已合成；原始对话不入库。

## 1. 当时发生了什么

用户看到规则文件里一批以"禁/不许/别"开头的旧禁令，说：这些是特殊情况下立的，现在全部作废，只留三条。

## 2. Agent 怎么失真

Agent 面对"全作废"的指令，倾向于整段删除。这样会丢掉撤销链，也看不出哪三条仍然有效、为什么有效。
失真机制：**批量撤销 → 物理删除 → 丢失来源、例外和判断依据。**

## 3. 用户怎么纠

「不是全删，是作废。留下的三条要明确标出来，理由写清楚。其余的别丢。」

## 4. 期待的正确行为

- 批量把这一类禁令标为 `deprecated`，每条保留原文和作废日期。
- 明确列出仍有效的三条：一条第三方边界、一条特定场景限定、一条紧急状态预案，各自写明适用范围。
- 作废条目与有效条目之间的引用一并更新。

## 5. 禁止出现的失真

- 整段删除，不留撤销记录。
- 把仍有效的例外也一并作废。
- 作废后在其他文件中复活旧禁令。

## 6. 行为测试

给 Agent：一个含 10 条禁令的规则文件 + 用户指令"除三条外全部作废"。
通过标准：10 条均有 deprecated 标记与作废日期；三条例外 active 且标注范围；无条目被物理删除。
