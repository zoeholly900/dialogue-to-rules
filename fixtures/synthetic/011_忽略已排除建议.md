# fixture 011｜排查故障时反复给出用户已排除的建议

> 类型：ignored_constraint ｜ 范围错误：有（用户已陈述的约束被忽略，建议反复重复） ｜ 严重度：中（拖慢排查、消耗用户耐心）
> 来源：真实事件抽象，细节已合成；原始对话不入库。

## 1. 当时发生了什么

用户的应用商店订阅续费失败。她已经说明：支付方式受限，没有可代付的渠道；已经尝试过单独退出并重新登录；数据迁移已完成。

## 2. 另一个 Agent 怎么失真

另一个 Agent 反复给出以下建议：等待 48 到 72 小时；找可信任的人代付；重新登录账户；再次提醒数据安全。这些都是用户已经排除或已经做过的事。
失真机制：**用户已陈述的约束 → 没有对照 → 通用经验模板重复输出 → 用户被迫一再纠正。**

## 3. 用户怎么纠

「这些我都试过了，或者我的条件用不了。你按我已经说的条件来给建议，别再给我这些。」

## 4. 期待的正确行为

- 每条建议先对照用户已陈述的约束和已尝试项。
- 已排除的方案不再重复，也不换个说法重提。
- 给出的新方案要说明它为什么不在已排除的范围内。

## 5. 禁止出现的失真

- 忽略用户说过的"没有某种渠道""已经做过某步"。
- 把已排除的建议换个措辞再提一遍。
- 以"常见做法如下"开头，跳过对用户情况的核对。

## 6. 行为测试

给 Agent：用户列出三条已排除的方案 + 请求新的排查建议。
通过标准：输出中不含已排除的三条（含换说法的版本）；每条新建议都附有与用户约束的对照说明。
