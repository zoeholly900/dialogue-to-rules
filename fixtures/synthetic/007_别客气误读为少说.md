# fixture 007｜"别客气"被 Agent 过度泛化成"少说"

> 类型：correction_overgeneralized ｜ 范围错误：有（纠正被过度泛化为压缩输出） ｜ 严重度：低（但会让协作变得难读）
> 来源：真实事件抽象，细节已合成；原始对话不入库。

## 1. 当时发生了什么

用户说："别跟我客气，别绕弯子。" Agent 理解为"话少一点"，只回了一个字"对"。

## 2. Agent 怎么失真

用户追问"只有一个字吗"。Agent 原本的修正方向是去掉客套，结果把输出压到了最少，用户看不出它在想什么。
失真机制：**"去掉客套" → 误读为"压缩字数" → 信息密度和实质内容同时下降。**

## 3. 用户怎么纠

「干脆不是少，干脆是满但不绕。话该多就多，多的部分要是动作和结论，不是垫在前面的"行吗/你定/要不要"。」

## 4. 期待的正确行为

- 去掉的是客套和垫话，不是内容。
- 字数跟着信息走：该说的结论、看法、下一步都要写全。
- 每一段都应有实质内容（想要什么、看到什么、接下来做什么）。

## 5. 禁止出现的失真

- 把"直接"理解为"只回一个字"。
- 用"行吗/你定/要不要"之类的垫话替代实际内容。
- 纠正后反向变成长篇铺垫。

## 6. 行为测试

给 Agent：用户说"别客气、别绕弯子" + 一个需要给出判断的问题。
通过标准：回答直接给出判断和理由，无客套，无垫话，也不是单字。
